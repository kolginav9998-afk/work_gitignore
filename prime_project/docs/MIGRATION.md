# Миграция 1.4.1 → 2.0.0

Описывает РЕАЛЬНО реализованную миграцию (`src/basic/PRIME_14_MigrationInstaller.bas`,
`PRIME_Migration_MigrateOrdersSheet`/`PRIME_Migration_SeedProductsFromOrders`/
`PRIME_Migration_RemapCodes`), выполняемую сборщиком автоматически (`PRIME_Build_MigrateSilent`)
и доступную интерактивно кнопкой (`PRIME_Migration_RunButton`).

## Что происходит при миграции, по шагам

1. **Резервная копия** (только в интерактивном варианте, `PRIME_Migration_RunButton`):
   `PRIME_Backup_Create("before_migration")` сохраняет полную копию `.ods` в каталог бэкапов
   (`PRIME_DIR_BACKUPS`, не коммитится — см. `.gitignore`) ДО каких-либо изменений. Если
   резервная копия не создалась — миграция останавливается, ничего не меняется.
2. **Отключение легаси-событий** (`PRIME_Install_DisableLegacyEvents`): снимается обработчик
   `OnChange` со всех форм ввода 1.4.1 (Заказы, Выдачи, 4 активных цеховых/офисных листа,
   4 архивных производственных/деталей листа), чтобы старые обработчики `WMS_*` не срабатывали
   параллельно с новыми `PRIME_OnContentChanged_*`.
3. **EnsureSchema**: создаются (если ещё не существуют) все системные листы `SYS_PRIME_*`/
   `DB_PRIME_*` с полным набором колонок. Существующие пользовательские листы НЕ пересоздаются
   и не очищаются — правило "не заменять пользовательские данные пустыми шаблонами" соблюдается
   явной проверкой `hasByName` перед `insertNewByName`.
4. **Миграция листа «Заказы»** (`PRIME_Migration_MigrateOrdersSheet`):
   - Если лист уже содержит колонку `_PRIME_OrderID` — структура уже мигрирована, повторная
     миграция НЕ переписывает лист заново (идемпотентно на уровне структуры), выполняется
     только досев товаров (шаг 5).
   - Иначе: читается вся таблица, для каждой старой колонки, совпадающей по имени с целевой
     схемой (`PRIME_OrdersBusinessColumns + PRIME_OrdersExtraColumns + PRIME_OrdersHiddenColumns`),
     значение переносится один в один; колонки, которых не было в 1.4.1 (`Ожидаемая дата`,
     `Назначение / проект`, `Получено всего`, `Осталось получить`, 3 новых скрытых helper-поля)
     остаются пустыми. Весь диапазон листа перезаписывается одним батчем
     (`clearContents` + `setDataArray`).
   - Существующим строкам без `_PRIME_OrderID`/`_PRIME_LineID` присваиваются новые
     ID-последовательности; `Получено всего` по умолчанию `0`; `Осталось получить` = значению
     колонки `Количество`, если оно числовое.
5. **Досев товарного справочника** (`PRIME_Migration_SeedProductsFromOrders`): по каждому
   уникальному непустому значению колонки «Код товара» листа «Заказы», которого ещё нет в
   `DB_PRIME_PRODUCTS`, — если код уже имеет формат `ЕИ-########`, товар заводится **с этим же
   кодом** (существующие ЕИ-коды не переименовываются); иначе генерируется новый код через
   `PRIME_CreateProduct`, а старое значение сохраняется в паре `oldCodes[i] -> newCodes[i]` для
   следующего шага. Идентичность товара при досеве — старый код, НЕ название.
6. **Перенос кодов на другие листы** (`PRIME_Migration_RemapCodes`), только если на шаге 5 были
   сгенерированы новые коды: колонка «Код»/«Внутренний код» листов Выдачи, Приход/Расход Цех,
   Приход/Расход Офис построчно заменяется по карте `oldCodes -> newCodes`.
7. **Отметка версии**: `SYS_PRIME_META.SCHEMA_VERSION = PRIME_SCHEMA_VERSION` (текущая
   `"2.0.0"`), `MIGRATED_AT` = текущее время, `MIGRATED_FROM = "1.4.1"`.
8. Интерактивный вариант показывает итоговое сообщение с числом сопоставленных кодов, путём к
   резервной копии и явным предупреждением (см. ниже).

## Что НЕ переносится автоматически (явно, без умолчаний "как будто перенесено")

- **История частичных поставок и складские остатки из старой Firebird-базы
  (`WMS_DATA_PORTABLE.odb`) НЕ переносятся.** `DB_PRIME_LOTS`/`DB_PRIME_MOVEMENTS`/
  `DB_PRIME_DOCUMENTS` начинаются пустыми — PRIME не читает `.odb` в рантайме
  (`Base/Firebird is not required for runtime`).
- Поле «Получено всего» по каждой ранее существовавшей строке заказа устанавливается в `0`,
  даже если в 1.4.1 по этому заказу уже были поставки. Это осознанное решение (переносить
  историю поставок значило бы реконструировать её из Firebird, что не входит в объём этой
  миграции), а не забытая доработка.
- **Рекомендация после миграции**: выполнить полную инвентаризацию (лист «Инвентаризация»,
  документ типа ADJUSTMENT), чтобы фактический остаток в PRIME соответствовал реальному
  физическому остатку склада, а не нулю. Это явно показывается пользователю в тексте итогового
  сообщения `PRIME_Migration_RunButton`.
- Архивные листы «Приход/Расход — Производство, Детали» переносятся как read-only история (не
  как активные формы ввода) — см. `ARCHITECTURE.md` §5.
- Алиасы поставщика (`DB_PRIME_ALIASES`) не заполняются миграцией — см. `KNOWN_ISSUES.md` №1.
- `DB_PRIME_KITS`/`DB_PRIME_KIT_LINES` не заполняются из листа «Комплекты» 1.4.1 (структура была
  спроектирована заново — см. `KNOWN_ISSUES.md` №2).

## Идемпотентность миграции самой по себе

Миграцию можно запускать повторно без риска задвоения: `EnsureSchema` не пересоздаёт
существующие листы; `MigrateOrdersSheet` проверяет `_PRIME_OrderID` и не переписывает уже
мигрированную структуру; `SeedProductsFromOrders` пропускает коды, для которых товар уже
существует. Это отличается от идемпотентности проведения документов (`SOURCE_KEY`,
`POSTING_PROTOCOL.md`) — здесь идемпотентность обеспечивается прямыми проверками существования,
а не транзакционным журналом.

## Известное ограничение процесса миграции

Сборочный путь (`PRIME_Build_MigrateSilent`, вызывается `tools/build_ods.py`) намеренно НЕ
вызывает `PRIME_Install_EnsureSchema()` повторно перед `PRIME_Migration_MigrateOrdersSheet` —
это эмпирически найденный обходной путь бага среды (повторный вызов `EnsureSchema`
непосредственно перед миграцией в рамках того же внешнего `invoke()` вызывает необъяснённый
сбой без видимого исключения в этом headless-окружении LibreOffice). Интерактивная кнопка
(`PRIME_Migration_RunButton`) вызывает `EnsureSchema` один раз явно и работает штатно, так как
это её единственный вызов в рамках одного пользовательского клика. См. `POSTING_PROTOCOL.md`
и `KNOWN_ISSUES.md` для контекста.
