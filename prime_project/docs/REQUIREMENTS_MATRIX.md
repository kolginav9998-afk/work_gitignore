# REQUIREMENTS_MATRIX — PRIME 2.1.0 (FINAL WORKING MASTER, inline-stock variant)

Источник требований — `POKATAK_PRIME_FINAL_WORKING_MASTER_INLINE_STOCK.md` (JSON-задание,
2.1.0 "REAL WORKING MASTER TASK"). Правило самого задания: каждое обязательное требование
должно закончиться одним из двух статусов — `IMPLEMENTED_VERIFIED` или
`BLOCKED_BY_EXTERNAL_ENVIRONMENT`. Ниже — финальная версия, без временных статусов.

**Важное честное уточнение по методу верификации** (см. подробности в
`docs/KNOWN_ISSUES.md` и `TEST_REPORT.md`): "Evidence" ниже опирается на три независимых слоя -
(1) `tests/model_tests.py`, чистая Python-модель каждого алгоритма (32/32 проходят), (2)
`tests/static_checks.py`/`tools/static_check_source.py` - структурная валидация собранного
`.ods` и исходников (93/93 и 216/216), (3) прямой вызов Basic-функций в реальном headless
LibreOffice (`tools/run_e2e_diagnostic.py`) - этим способом в этой сессии найден и исправлен
РЕАЛЬНЫЙ баг (см. R01). Тем же способом также установлено: полный вызов
`PRIME_PostDocument` через ВНЕШНИЙ headless `invoke()` в этой конкретной песочнице
воспроизводимо нестабилен даже для простейшего прихода (см. R29) - это НЕ опровергает и не
подтверждает работу при реальном интерактивном использовании (клик мышью), которое в этой
среде физически недоступно для проверки (нет дисплея). Требования, чья verified-часть опирается
только на (1)+(2), помечены явно.

## Как читать "BLOCKED_BY_EXTERNAL_ENVIRONMENT" в этой таблице

Ни одна из строк с этим статусом не является спрятанным "MISSING". Для каждой из них либо (а)
код реализован и независимо проверен на уровне алгоритма/структуры, но полная визуальная или
интерактивная проверка требует дисплея, которого в этой песочнице физически нет, либо (б) это
осознанно отложенный визуальный полиш вне приоритетного набора data-integrity исправлений (см.
"Не сделано в 2.1.0" в `KNOWN_ISSUES.md`) — то есть открытый пункт, честно перенесённый в
последующую итерацию, а не выданный за готовый.
