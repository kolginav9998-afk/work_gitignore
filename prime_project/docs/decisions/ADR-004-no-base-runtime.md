# ADR-004: LibreOffice Base не требуется для запуска и обычной работы

## Статус
Принято.

## Контекст
Связано с ADR-001, но фокус здесь — на пользовательском опыте запуска, а не на архитектуре
хранения: в 1.4.1 книга Calc открывалась вместе с зарегистрированным источником данных Base,
что означало дополнительную точку отказа при первом открытии на новой машине (путь к `.odb`,
драйвер Firebird, права доступа к файлу) ещё до того, как пользователь вообще начал работать
со складом.

## Решение
`ПОКАТАК_PRIME_2.0.0.ods`, полученный сборщиком (`tools/build_ods.py`), открывается и работает
как обычная книга Calc с макросами — без зарегистрированного источника данных Base, без
диалогов подключения к БД при открытии. `WMS_DATA_PORTABLE.odb` остаётся в
`legacy_reference/` как опциональный, не подключаемый по умолчанию, источник для
одноразового read-only импорта истории, если он когда-либо понадобится отдельным
инструментом миграции вне рантайма PRIME.

## Последствия
- Файл `.ods` можно скопировать/открыть на любой машине с LibreOffice Calc без сопутствующей
  установки/настройки Base-источника — единственная зависимость среды выполнения:
  `libreoffice-calc` с включёнными макросами.
- CI (`tools/build_ods.py`, `tests/static_checks.py`) не требует эмуляции Base/Firebird-
  окружения — только `libreoffice-calc` + `xvfb`, что упрощает и ускоряет пайплайн.
- Любая будущая миграция реальной истории из `WMS_DATA_PORTABLE.odb` должна оставаться
  отдельным, явно вызываемым, не входящим в обычный рантайм PRIME инструментом — не
  зависимостью, без которой книга не открывается.
