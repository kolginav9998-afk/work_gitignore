# Обновление PRIME 2.0.1 → 2.1.0

## Перед обновлением

1. Закройте книгу, сделайте резервную копию файла (кнопка "Создать резервную копию" на листе
   "Инфо" тоже подойдёт, если файл ещё открыт).
2. Обновление меняет структуру нескольких скрытых системных листов (добавляет колонки
   STOCK_CONTOUR, OP_ID, PARENT_LOT_ID и т.д. в конец их заголовков) и физически переименовывает
   лист "Остаток" в "Наличие". Оба действия неразрушительны для существующих данных (см. ниже),
   но по общему правилу проекта — сначала бэкап, потом обновление.

## Что делает обновление автоматически

- `PRIME_Migration_UpgradeHiddenSchemaTo210` дописывает недостающие 2.1.0-колонки в конец
  заголовка уже существующих `DB_PRIME_DOCUMENTS`/`MOVEMENTS`/`LOTS`/`RETURNS`/`ORDER_SNAPSHOT` —
  старые колонки и данные не трогаются, новые ячейки в старых строках останутся пустыми (что
  корректно читается кодом как "не COMMITTED"/"без родительской партии"/"общий контур" и т.п.).
- `PRIME_Migration_RenameStockToNalichie` переименовывает лист "Остаток" в "Наличие", только
  если "Наличие" ещё не существует — идемпотентно, безопасно запускать повторно.
- Новые листы "Перемещения"/"Журнал" создаются с нуля (`PRIME_Install_EnsureBusinessSheet`).
- 24 ранее видимые кнопки-заглушки скрываются (не удаляются) — данные листов не меняются.

## Что НЕ переносится автоматически из старых данных

- **Существующие партии/движения, созданные до 2.1.0, не имеют значения STOCK_CONTOUR** —
  колонка появляется пустой. Весь такой старый остаток фактически трактуется кодом как контур
  `""` (пустая строка), который НЕ совпадает ни с `GENERAL`, ни с `WORKSHOP_DETAILS`, ни с
  `OFFICE` при точном сравнении в `PRIME_FifoLotsForProduct`/`PRIME_StockByLocation` с явно
  указанным контуром. **Практическое следствие: старый остаток, накопленный до обновления, не
  будет виден в новых inline-колонках "В наличии"/"Остаток деталей" и т.п., которые всегда
  запрашивают конкретный контур.** Он остаётся виден на сводном листе "Наличие" при фильтре
  "Все" (без фильтра по контуру) — используйте эту кнопку сразу после обновления, чтобы
  свериться со старым остатком.
- Рекомендация: после обновления выполните инвентаризацию (лист "Инвентаризация") — она читает
  остаток через `PRIME_StockByLocation` с `contourFilter=""`, то есть увидит и старые
  безконтурные, и новые контурные движения, и позволит провести корректировку, которая уже
  создаст правильно классифицированные по контуру партии going forward.
- **Существующие RETURN-строки не имеют OP_ID** — до тех пор, пока по ним не проверяется новый
  код (`PRIME_AlreadyReturnedQtyBase` трактует отсутствие OP_ID как "не блокировать", см. её
  реализацию), это не блокирует работу, но не даёт задним числом гарантии committed-only для
  исторических возвратов.

## Что делать после обновления

1. Откройте лист "Наличие" (бывший "Остаток"), нажмите "Показать всё" — сверьте с ожидаемым
   остатком.
2. При необходимости проведите инвентаризацию для явной классификации старого остатка по
   контурам (см. выше).
3. Для листов "Перемещения" и "Журнал" — они начинают пустыми, это нормально (это НОВЫЙ
   функционал, а не миграция существующих перемещений/журнала).

См. также `docs/CHANGELOG.md` (полный список изменений) и `docs/REQUIREMENTS_MATRIX.md`
(построчный статус каждого обязательного требования).
